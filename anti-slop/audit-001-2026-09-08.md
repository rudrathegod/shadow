## Findings

### 1. [MEDIUM] [FIXED] Palette is an accident of cascade order, not a decision — R-01, R-20, R-29, R-31
`renderer/styles.css:107-187`

The file has five sequential comment-labeled blocks, each re-declaring styles for the same selectors instead of editing the earlier rule:
- `/* Neutral desktop surface */` (line 49)
- `/* Transcript and command hierarchy */` (line 107)
- `/* Balanced controls */` (line 124)
- `/* Catppuccin Mocha terminal language */` (line 142)
- `/* Black + light-blue palette */` (line 165)
- `/* Neon green is reserved for active context... */` (line 175)

The rendered result depends on cascade order and scattered `!important` flags, not one identity. Example: `.tb-divider` background is set to Catppuccin's `#45475a` at line 149 and nothing later touches it, so the toolbar divider is still lavender-grey while sibling elements (`.panel-kicker`, `.act-primary`) were pulled forward to neon green (`#39ff14`) by the final block. You cannot write a one-line reason for "why is the divider lavender and the kicker green" — it's leftover from a design pass that didn't get finished, not a choice.

Fix: pick the actual current palette (looks like neon-green accent + neutral dark, per the last block and CLAUDE.md's `e48320b` commit), delete the superseded blocks entirely instead of leaving them to be silently overridden, and confirm every selector still resolves to that palette.

### 2. [LOW-MEDIUM] [FIXED] Generic AI iconography on the primary actions — R-04
`renderer/renderer.js:11-12`, `renderer/icons.js:5-6`

The flagship "Assist" button and the "Say" button use `sparkles` and `wand-sparkles` — the canonical generic-AI glyphs called out by name in the skill. The hand-rolled icon set itself (24x24 viewBox, round caps/joins, `currentColor` stroke) is a reasonable no-dependency choice given the project bans new runtime deps, but the specific glyph choice for the two primary actions is the generic default with no stated relevance to "assist" or "say" specifically.

Fix: either state the reason (e.g. "sparkles = AI-generated response, kept because X") or swap to something that maps to the actual action (e.g. a chat/message glyph for Assist, a speech-bubble for Say).

### 3. [LOW] [FIXED] Dead CSS left by the same cascade issue as #1
`renderer/styles.css:34` vs `:178`, `:169` vs `:178`

`.act-primary { color:#fff; ... }` (line 34) never renders — line 178 always wins. `.smart-pill.on { background:#a7f3d0; color:#0c0c0d }` (line 169) never renders — same. Not an antislop pattern by itself, but it's the direct cost of #1: editing line 34 today does nothing, which will confuse whoever touches it next.

Fix: delete once #1 is resolved (the dead rules disappear along with the superseded blocks).
